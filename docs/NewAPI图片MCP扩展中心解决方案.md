# New API 图片 MCP 与扩展中心解决方案

版本：V1.0  
日期：2026-11-03  
定位：完整目标方案，一次建设到位；不包含实现代码。

## 1. 建设目标

在尽量跟随 New API 官方版本、减少后续合并成本的前提下，建设一套配置驱动的扩展体系，并首先落地图片扩展。

最终形成以下产品形态：

- New API 内置 Chat、Playground、MCP 中心，以及按配置注册的外部应用入口。
- 图片工坊作为独立外部扩展，与 Chat、Playground 在导航体验上平级。
- MCP 使用独立域名，对外提供统一聚合入口。
- 图片扩展同时提供用户 UI、管理 UI 和标准 MCP 能力。
- 图片调用以 `image.generations` 为核心工具，统一支持文生图和图生图，不再拆分独立的图片编辑 MCP 工具。
- 新图片模型通过模型画像、模板继承、LLM 辅助配置和真实测试接入，无需逐模型开发 MCP 工具。
- 用户身份、分组、额度、渠道选择、模型映射、计费和日志继续由 New API 负责。

## 2. 核心设计决策

| 决策项 | 最终方案 |
|---|---|
| New API 改造方式 | 只增加通用扩展控制面，不写入图片业务逻辑 |
| 图片应用 | 独立仓库、独立部署、独立数据库和文件存储 |
| MCP 公网入口 | 独立域名下的统一 MCP Gateway |
| 多扩展接入 | Gateway 聚合，扩展 MCP Server 不直接暴露公网 |
| 子应用界面 | New API 通用 Shell＋iframe，避免构建依赖耦合 |
| New API 与扩展交互 | 公开 HTTP API、一次性票据和委托凭证，不共享数据库 |
| 图片主工具 | `image.generations`，统一文生图与图生图 |
| 动态模型方式 | 固定 MCP 工具、动态模型注册、动态能力画像 |
| 自动配置 | 规则优先，LLM 生成草稿，确定性校验和真实测试决定发布 |
| MCP 中心 | 快速接入、能力目录、完整调试台、调用记录和扩展管理一次交付 |

## 3. 总体架构

### 3.1 公网与组件边界

正式 MCP 地址采用独立域名，例如 `mcp.example.com/mcp`。该地址只指向独立 MCP Gateway，不指向 New API Relay，也不直接指向图片扩展。

New API 继续提供原有模型服务，并增加通用扩展注册、导航挂载、启动票据、委托授权和 MCP 中心页面。

MCP Gateway 独立部署，负责协议接入、扩展聚合、权限过滤、路由、会话、限流、调试追踪和审计。

图片工坊独立部署，包含图片 UI、图片 MCP Server、模型注册中心、自动配置服务和图片资产存储。

其他扩展可以采用纯 UI、纯 MCP、UI＋MCP 或纯后台服务形态，复用同一套注册和授权机制。

### 3.2 调用链路

用户通过图片工坊 UI 生成图片时，请求由图片应用校验，再通过用户委托凭证调用 New API 图片接口。

Agent 通过 MCP 生成图片时，请求先进入独立 MCP Gateway。Gateway 完成身份和权限校验后，将调用路由至图片 MCP Server。图片 MCP Server 校验模型画像和参数，再调用 New API。New API 完成渠道选择、模型映射、上游调用、额度、计费和日志记录。

New API 的 MCP 调试台采用相同链路，不绕过 Gateway，不使用管理员服务账号代替当前用户。

## 4. New API 通用扩展控制面

New API 主仓的修改长期限制在以下四组通用能力中。

### 4.1 扩展注册中心

一个扩展通过配置声明自身能力，而不是在 UI、MCP 等类型中单选。注册信息包括：

- 扩展 ID、名称、图标、版本、说明和启用状态。
- 用户 UI、管理 UI、MCP Server、后台服务等能力列表。
- 导航位置、内部路由、外部入口、展示方式和排序。
- 可见用户、分组、角色和授权范围。
- 健康检查、契约版本、文档地址和配置 Schema。
- MCP 地址、传输方式、命名空间和允许暴露的能力范围。

纯 MCP 扩展不显示在主导航；只有声明主导航 UI 的扩展才与 Chat、Playground 平级。

### 4.2 通用子应用容器

采用 New API 通用 Shell＋iframe 的集成方式。Shell 负责导航、权限检查、单点登录、主题与语言、深链接、全屏、新窗口和维护状态。外部扩展独立选择前端技术栈，不使用 Module Federation，不共享构建产物。

### 4.3 通用身份与委托授权

浏览器子应用使用短时、单次、绑定目标扩展的启动票据。扩展服务端兑换票据后建立自己的 HttpOnly 会话。

MCP 客户端使用专用访问令牌或 OAuth。Gateway 验证客户端后，以获得真实用户授权的委托凭证访问 New API。委托凭证短期有效、可撤销，并限定扩展、能力和用户范围。

### 4.4 内置 MCP 中心

MCP 中心是通用展示和调试前端，与 Playground 使用一致的工作台规范。协议执行仍由独立 Gateway 和扩展完成。

## 5. 独立 MCP Gateway

Gateway 是多扩展的唯一公网 MCP 数据入口，职责包括：

- MCP 协议接入、会话管理、流式响应、超时和取消。
- 聚合工具、资源和提示词。
- 按用户、客户端和扩展过滤可见能力。
- 使用扩展 ID 作为命名空间，避免工具重名。
- 缓存扩展能力，处理动态上线、下线和能力变更。
- 用户、客户端、扩展和工具级限流。
- 扩展健康检查、熔断和故障隔离。
- 调试支持、协议事件追踪、指标和审计。
- 高风险能力控制和调用来源记录。

Gateway 不维护 New API 用户表，不处理渠道调度，不保存图片模型画像，也不实现具体扩展业务。

单扩展调试地址可以由 Gateway 提供，但正式默认入口仍是统一聚合地址，不要求每个扩展使用独立公网域名。

## 6. New API MCP 中心

### 6.1 快速接入

提供正式 MCP 地址、当前账号授权状态、Gateway 健康状态、可用扩展数量、专用凭证入口和客户端教程。

客户端教程配置驱动维护，包括客户端名称、平台、说明、配置模板、文档链接、启用状态和排序。只展示经过验证的专用模板，其余使用通用 MCP 客户端说明。

### 6.2 能力目录

动态展示当前用户可使用的工具、资源和提示词，包括名称、说明、输入输出 Schema、所属扩展、权限要求、风险等级、使用示例和健康状态。

支持按扩展、能力类型、权限和状态筛选，并可直接进入对应能力的调试页面。

### 6.3 完整调试台

调试台采用三栏工作台：

- 左侧：扩展与能力选择。
- 中间：参数表单或原始参数编辑。
- 右侧：结果、原始响应和协议追踪。

功能包括 Schema 表单、JSON 编辑、工具调用、资源读取、提示词调试、会话重建、结果预览、请求 ID、耗时、错误诊断、参数模板、历史重放和链路查看。

调试请求继承当前用户权限。非只读操作需要二次确认，高风险工具必须提前获得明确授权。

### 6.4 调用记录与管理

调用记录支持按用户、客户端、扩展、工具、状态和时间查询，展示延迟、请求 ID、链路 ID、错误类型和关联模型费用。

管理功能包括扩展注册、权限配置、健康状态、能力缓存刷新、限流、客户端教程、审计和高风险工具禁用。

## 7. 图片扩展能力边界

图片工坊同时注册三种入口：

| 入口 | 使用对象 | 主要职责 |
|---|---|---|
| 用户 UI | New API 登录用户 | 文生图、图生图、模型选择、历史和下载 |
| 管理 UI | 管理员 | 模型画像、自动配置、测试、发布和回滚 |
| 图片 MCP | Agent 与调试台 | 图片生成、模型发现和任务管理 |

图片扩展不实现 New API 渠道调度，不直接访问 New API 内部数据库，不保存上游供应商密钥。

## 8. 图片 MCP 工具设计

### 8.1 固定工具集合

图片扩展对外提供以下稳定工具：

| 工具 | 作用 |
|---|---|
| `image.generations` | 统一文生图与图生图，是核心图片工具 |
| `image.list_models` | 查询当前用户可调用的图片模型 |
| `image.get_model_capabilities` | 查询模型尺寸、质量、输入限制和双模式支持情况 |
| `image.get_task` | 查询长任务状态与结果 |
| `image.cancel_task` | 取消尚未完成的异步任务 |

不设置独立的 `image.edit` MCP 工具，避免调用方在文生图、图生图和图片编辑之间理解多套业务概念。模型动态增加时也不增加新的 MCP 工具。

### 8.2 `image.generations` 输入模式

`image.generations` 通过显式模式区分生成方式：

| 模式 | 含义 | 必需输入 |
|---|---|---|
| 文生图 | 仅根据文本提示生成图片 | 提示词 |
| 图生图 | 根据一张或多张参考图及文本提示生成新图片 | 参考图＋提示词 |

主要参数包括：

| 参数 | 说明 |
|---|---|
| 模式 | 文生图或图生图，默认文生图 |
| 提示词 | 描述主体、环境、风格或希望保留与改变的内容 |
| 参考图 | 图生图模式必填，支持受控图片 URL 或图片资产 ID |
| 模型 | 指定模型，或使用自动选择 |
| 尺寸 | 由目标模型能力画像约束 |
| 质量 | 快速、标准、高质量等抽象档位 |
| 数量 | 受模型和用户配额共同限制 |
| 输出格式 | PNG、JPEG、WebP 等模型实际支持格式 |
| 重绘强度 | 图生图可选，仅在模型画像声明支持时开放 |
| 扩展参数 | 仅允许模型画像中明确声明的附加参数 |

图片扩展在调用前检查模式与模型能力：图生图模型必须声明支持参考图输入；参考图数量、格式、大小和尺寸必须符合模型限制；不支持的参数应在本地拒绝，而不是直接透传上游。

### 8.3 底层图片端点映射

New API 图片端点以 `/v1/images/generations` 为主。

文生图直接映射到该端点。图生图优先在同一图片生成契约中携带参考图输入，由 New API 或图片适配层根据模型画像完成参数映射。

若某个上游仅能通过 OpenAI Images Edits 兼容端点完成图生图，则允许适配层在内部转换调用，但该差异不得暴露为新的 MCP 工具。对外仍保持 `image.generations` 和统一结果结构。

因此，MCP 契约稳定，上游端点差异由模型画像和适配层消化。

### 8.4 统一返回结果

生成结果至少包含：

- 任务状态和请求 ID。
- 实际模型、生成模式和配置版本。
- 图片资产 URL 或资产 ID。
- 宽高、格式、文件大小和数量。
- 可记录的用量和费用信息。
- 可重试与不可重试的错误分类。
- 异步任务标识和过期时间（如适用）。

MCP 默认返回受控图片 URL 或资源链接，不把大图片 Base64 放入协议响应。上游返回 Base64 时，由图片扩展转存后返回资源链接。

## 9. 动态图片模型注册中心

### 9.1 三层模型画像

模型配置采用继承结构：

1. OpenAI Images 基础模板：通用协议、标准参数和默认结果处理。
2. 供应商或模型系列模板：某一系列共同能力和参数差异。
3. 具体模型覆盖：仅描述模型特有约束。

### 9.2 模型画像内容

| 类别 | 主要内容 |
|---|---|
| 基本信息 | 对外模型名、上游模型名、协议类型、画像版本 |
| 生成能力 | 文生图、图生图、多参考图、批量生成 |
| 参数约束 | 尺寸、质量、数量、格式、默认值和禁用参数 |
| 输入限制 | 参考图数量、格式、大小、宽高和资源类型 |
| 参数映射 | 标准参数到上游参数的转换和剔除策略 |
| 输出处理 | URL、Base64、转存、过期时间和结果校验 |
| 执行策略 | 同步或异步、超时、幂等、重试和费用上限 |
| 验证策略 | 文生图测试、图生图测试、预算和发布条件 |
| 配置来源 | 人工、模板、LLM、真实探测及字段证据 |

### 9.3 动态生效

模型画像保存在图片扩展自己的数据库中，带有配置版本、状态、生效时间、来源、审核记录和上一稳定版本。

发布后更新注册中心版本并刷新各实例缓存，不重启 New API、图片扩展或 MCP Gateway，也不中断已有 MCP 会话。

MCP 工具定义保持不变。客户端通过模型查询工具获取最新模型列表，通过能力查询工具获取具体参数约束。

## 10. 新模型自动配置与发布

### 10.1 模型发现

候选模型来源于新增或更新渠道、同步可见模型列表、管理员导入和供应商模板。发现只进入候选状态，不直接对 MCP 用户开放。

### 10.2 规则优先

优先检查是否存在同系列模板、相同上游画像、明确协议声明、可用渠道、价格、分组和权限配置。能够确定性继承的模型直接生成配置草稿，不调用 LLM。

### 10.3 LLM 辅助配置

无法确定的字段由内置文本模型辅助生成。输入包括模型名称、供应商、协议类型、管理员提供的文档、上游 Schema、已验证同系列画像和可执行测试项。

LLM 只输出配置草稿、字段依据、置信度、未知字段和建议测试。不得仅凭模型名称猜测能力，不得直接修改渠道地址、密钥、计费、权限或发布状态。

### 10.4 确定性校验

静态校验包括配置 Schema、参数依赖、模型映射冲突、渠道与价格完整性、权限范围、参考图约束和禁止字段。

真实测试至少覆盖：

- 最小成本文生图，验证返回结构、图片解码、实际尺寸和格式。
- 声明图生图时，使用固定小图和提示词验证参考图输入与结果。
- 非法尺寸、空参考图、超限文件等负向用例，验证本地拦截。
- 用量、费用、日志和请求 ID 归集。
- 异步模型的任务查询、取消和超时行为。

### 10.5 发布策略

支持人工发布、自动测试后人工发布、受信供应商测试通过后自动发布。自动发布必须满足模板已验证、未知映射为零、双模式测试按声明通过、价格权限完整、预算未超限且可回滚。

模型状态包括候选、草稿、待验证、待发布、已启用、降级、停用和回滚。

## 11. 认证、权限与费用归属

UI 使用一次性启动票据，MCP 使用专用访问令牌或 OAuth。图片扩展和 Gateway 不读取 New API 用户表。

每次图片调用同时记录真实用户、来源客户端、来源扩展和委托凭证。New API 按真实用户执行分组、额度和费用控制。

配置助手使用独立文本模型服务身份；模型验证使用独立低预算图片服务身份。两者与普通用户凭证隔离。

权限至少区分模型查询、文生图、图生图、任务查询、任务取消、MCP 调试和扩展管理。导航可见性不作为安全边界，Gateway 和 New API 必须再次鉴权。

## 12. 数据与部署边界

| 组件 | 数据与部署责任 |
|---|---|
| New API | 用户、分组、令牌、渠道、额度、计费和通用扩展注册 |
| MCP Gateway | 独立扩缩容；会话、能力缓存、限流和短期运行状态 |
| 图片扩展 | 模型画像、候选模型、验证记录、发布版本、图片任务和审计 |
| 图片存储 | 原图、参考图、结果图、缩略图和过期策略 |
| 可观测系统 | 指标、链路、错误和审计汇总 |

禁止直接访问彼此内部数据库。外部标识使用模型名、扩展 ID 等稳定引用，不依赖 New API 内部数据库主键。

## 13. 安全与可靠性要求

- 扩展地址必须经管理员审核，并配置服务端出口白名单，防止 SSRF。
- 长期令牌不得出现在 URL、iframe、前端配置或日志中。
- 参考图和结果图下载需要权限、有效期、大小和格式校验。
- 调试台不得调用未注册扩展，不得任意添加鉴权请求头。
- 图片生成属于非幂等计费操作，不自动盲目重试。
- 客户端重复提交时使用幂等键关联已有任务，避免重复扣费。
- 限流维度覆盖用户、客户端、扩展、模型和工具。
- 单扩展故障不得影响 New API、Gateway 或其他扩展。
- 默认只记录调用元数据；提示词、图片地址和完整响应按策略脱敏。
- 文档和扩展描述采用安全渲染，禁止脚本注入。
- 配置和模型画像支持审计、灰度、停用和一键回滚。

## 14. 配置项清单

New API 通用配置包括 MCP 功能开关、公开地址、Gateway 内部地址、导航开关、页面可见范围、调试开关、客户端教程、默认超时和自定义文档。

扩展注册配置包括 UI、MCP、健康检查、权限、可见范围、展示方式、文档和契约版本。

图片扩展配置包括 New API 地址、配置助手服务身份、验证服务身份、测试预算、模型同步策略、受信供应商、自动发布条件、图片存储和结果过期策略。

公开地址与内部地址分离。密钥使用服务端密钥引用，不进入扩展清单和浏览器。

## 15. 端到端验收标准

1. 纯 UI、纯 MCP、UI＋MCP 扩展均可仅通过配置注册。
2. 图片工坊在导航上与 Chat、Playground 平级，代码和部署保持独立。
3. Agent 能通过独立 MCP 域名发现并调用有权限的多个扩展。
4. MCP 中心具备快速接入、能力目录、完整调试台、调用记录和扩展管理。
5. `image.generations` 能完成文生图，并能在同一切换入口完成图生图。
6. 图生图可传入参考图和提示词，参考图限制在调用前生效。
7. 不依赖独立图片编辑 MCP 工具，上游端点差异对调用方透明。
8. 新模型完成配置、测试和发布后，无需重启即可被原有生成工具调用。
9. 模型能力查询能准确返回文生图、图生图、尺寸、质量和输入限制。
10. 图片费用、额度和日志正确归属真实用户。
11. 调试台无法越权，扩展故障和工具重名不会影响其他能力。
12. New API 主仓不包含图片业务代码，后续官方升级只维护通用扩展控制面。

## 16. 最终边界

New API 是统一门户、身份中心、模型网关和费用治理中心；MCP Gateway 是独立协议与扩展运行入口；图片工坊是独立业务扩展。

图片能力对外只围绕 `image.generations` 建立统一生成体验：文生图和图生图共享工具、模型选择、权限、任务与结果契约；模型差异和上游端点差异全部由配置画像与适配层处理。
